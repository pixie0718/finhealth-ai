2. Problem Statement Analysis

Challenge Statement (IDBI Innovate Track 03)

"Bank's MSME credit evaluation relies on traditional financial documents, which many New-to-Credit (NTC) and New-to-Bank (NTB) enterprises lack or maintain inadequately. Despite availability of rich alternate data (GST, UPI, AA, EPFO, etc.), absence of a unified assessment framework leads to high rejection rates, missed viable borrowers, limited portfolio diversification, and slower financial inclusion progress."

❌ Current Problem:
  • 30M+ MSMEs credit-invisible
  • Rejected by manual underwriting
  • Viable borrowers missed
  • No alternate data framework
  • Portfolio lacks diversification
  • Slow financial inclusion
✅ Our Solution:
  • Aggregate GST, UPI, AA, EPFO
  • Score in 2 seconds
  • Fair NTC assessment
  • Explainable decisions
  • Instant loan eligibility
  • Bank integration ready
📊 Impact Potential: A financial health assessment system that converts 30M credit-invisible MSMEs into creditworthy borrowers, enabling ₹100K+ loans per MSME and ₹3T+ new credit disbursement across Indian banking sector.

Data Flow: GSTIN to Credit Decision

Step 1: MSME Enters GSTIN

Business owner inputs 15-digit GSTIN in simple web form

Step 2: Consent Generation

System generates RBI Account Aggregator consent artifact (time-bound, revocable)

Step 3: Data Aggregation

Fetch 18-month GST filing, UPI/bank activity, EPFO payroll, CIBIL (if available)

Step 4: Feature Engineering

Extract 23 financial features from raw data (cash flow, compliance, growth, stability)

Step 5: ML Scoring

XGBoost model predicts creditworthiness + 5-pillar breakdown

Step 6: Explainability

SHAP shows top 3 strengths & 3 risks driving the score

Step 7: Loan Eligibility

System calculates eligible amounts and matched products (MUDRA, CGTMSE, etc.)

Step 8: Real Loan Application

MSME applies for loan; banker reviews in dashboard; decision recorded

4. Features Implemented

4.1 Financial Health Scoring (5-Pillar System)

Pillar Weight Features Data Source
💰 Cash Flow 25-30% Inflow/outflow ratio, stability, bounce rate, balance ratio UPI/Bank AA
📋 Compliance 20-24% GST filing rate, EPFO compliance, tax-to-revenue ratio GST, EPFO
📈 Growth 20-23% Revenue growth, employee growth, revenue trend GST, EPFO
🔐 Stability 20-23% Revenue volatility, buyer diversity, salary stability, tenure GST, EPFO, UPI
💳 Credit Worthiness 15% (0% NTC) CIBIL score, DPD, active loans CIBIL

NTC Mode: When business has no CIBIL history, credit pillar weight (15%) is redistributed to alternate-data pillars (Cash Flow 30%, Compliance 24%, Growth 23%, Stability 23%), ensuring fair scoring.

Priority 1: OCEN Bank Integration (4 hours)

What: Create mock OCEN endpoint showing credit request/response flow
Why: Proves your system can talk to bank's OCEN node
Impact: High credibility with judges

# backend/routers/ocen.py - NEW FILE @router.post("/api/ocen/submit-credit-request") async def submit_to_ocen_node( msme_id: str, score_record: dict, current_user = Depends(get_current_banker) ): """ Submit credit assessment to bank's OCEN node. Real flow: POST to /ecl/creditRequest on bank's OCEN endpoint. """ # Build OCEN-standard credit request ocen_request = { "requestId": f"OCEN-{msme_id}-{datetime.now().timestamp()}", "borrowerConsentId": score_record["consent_id"], "creditRequest": { "gstin": score_record["gstin"], "businessName": score_record["business_name"], "requestedAmount": score_record["eligible_loan_amount"], }, "creditAssessment": { "overallScore": score_record["overall_score"], "riskBand": score_record["risk_band"], "pillars": { "cashFlow": score_record["cash_flow"], "compliance": score_record["compliance"], "growth": score_record["growth"], "stability": score_record["stability"], }, "dataSourcesUsed": ["GST", "UPI/AA", "EPFO"], }, "timestamp": datetime.utcnow().isoformat(), } # Simulate OCEN node response ocen_response = { "status": "SUCCESS", "requestId": ocen_request["requestId"], "bankDecision": { "status": "APPROVED" if score_record["overall_score"] >= 60 else "REVIEW_REQUIRED", "recommendedAmount": score_record["eligible_loan_amount"], "processingTimeMinutes": 2, }, "receivedAt": datetime.utcnow().isoformat(), } return ocen_response

Priority 2: Audit Logging & Compliance (3 hours)

What: Log every API call, data access, consent generation
Why: Banks need compliance verification
Impact: Regulatory readiness

# backend/models/audit.py - NEW FILE class AuditLog(Base): __tablename__ = "audit_logs" id = Column(Integer, primary_key=True) user_id = Column(String, index=True) user_email = Column(String) action = Column(String) # "SCORE_GENERATED", "APPLICATION_SUBMITTED", etc. msme_id = Column(String, nullable=True) gstin = Column(String, nullable=True) # What data was accessed data_accessed = Column(JSON) # {"gst": true, "upi": true, "epfo": true} details = Column(JSON) ip_address = Column(String, nullable=True) created_at = Column(DateTime, default=datetime.utcnow, index=True) # Middleware logs all API calls async def audit_middleware(request: Request, call_next): response = await call_next(request) if request.url.path.startswith("/api/"): audit = AuditLog( user_email=get_user_from_token(request), action=f"{request.method} {request.url.path}", details={"status_code": response.status_code}, ip_address=request.client.host ) db.add(audit) db.commit() return response
